🎯 Keep scry CLI diagnostic artifact I/O non-authoritative, including writes performed while a runner is still executing. The result sink must contain sanitizer, temporary-write, atomic-move, and cleanup failures; record bounded `:scry.cli/diagnostic-error` metadata; and return control so later tests still run. Canonical runner results and normal outcome precedence remain authoritative.

After a normal runner return, reconcile once and retry missing artifacts. If the runner throws first, do not invent a final result: preserve already published `:result-files`, report unresolved callback-known writes, and retain `:scry.cli/runner-error`. Use `:final-result-file-reconciliation` after any normal return and `:incremental-result-file-writing` only when runner failure prevents reconciliation.

Containment is deliberately asymmetric: filesystem diagnostics are secondary, but terminal progress writer/flush failures remain primary-output failures and may follow the ordinary runner-error path. Catch-path rendering must itself be best-effort so it cannot erase the original structured outcome.
